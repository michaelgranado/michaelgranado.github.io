strategy

To create a correct CUDA renderer that satisfies both atomicity and ordering requirements, I'll implement the following strategy:

  1. Modify the rendering approach to ensure all updates to a pixel respect the order of circles.
  2. Implement an atomic update mechanism to handle race conditions when multiple threads try to update the same pixel.
  3. Restructure the rendering algorithm by dividing the work based on pixels rather than circles, ensuring that each pixel's updates are processed sequentially in the correct order.
  4. Use a per-pixel approach where each thread will handle a specific pixel and iterate through all circles that might contribute to that pixel in the original order.
  5. Leverage the circleBoxTest utility functions to efficiently determine which circles contribute to each pixel.

reasoning

The current implementation in the starter code has two major issues:

  1. Lack of Atomicity: The current code assigns one thread per circle, but when multiple circles overlap and contribute to the same pixel, multiple threads can concurrently read and write to the same pixel memory location, leading to race conditions.
  2. Incorrect Order: Since each circle is processed by a different thread, there's no guarantee that the circles' contributions to a pixel will be processed in the original order provided by the application.

My pixel-centric approach addresses both issues:

  • By assigning one thread to each pixel, we ensure that only one thread is ever writing to a particular memory location, eliminating the need for atomic operations or locks.
  • Each thread will sequentially process all circles that might contribute to its assigned pixel in the exact order they were provided, ensuring the correct rendering of transparent circles.
  • This approach is conceptually cleaner, as it aligns with the compositing model: each pixel in the final image is the result of sequential contributions from ordered circles.

While this approach may not be the most performance-optimized (since a thread might check many circles that don't affect its pixel), it ensures correctness, which is our primary goal.

// kernelRenderPixels -- (CUDA device code)
//
// A pixel-centric approach to render circles. Each thread is responsible for
// a single pixel and processes all circles that might contribute to that pixel
// in sequential order to ensure proper transparency handling.
__global__ void kernelRenderPixels() {
    int pixelX = blockIdx.x * blockDim.x + threadIdx.x;
    int pixelY = blockIdx.y * blockDim.y + threadIdx.y;
    
    int imageWidth = cuConstRendererParams.imageWidth;
    int imageHeight = cuConstRendererParams.imageHeight;
    
    if (pixelX >= imageWidth || pixelY >= imageHeight)
        return;
    
    float invWidth = 1.f / imageWidth;
    float invHeight = 1.f / imageHeight;
    
    float2 pixelCenterNorm = make_float2(invWidth * (static_cast<float>(pixelX) + 0.5f),
                                         invHeight * (static_cast<float>(pixelY) + 0.5f));
    
    int pixelOffset = 4 * (pixelY * imageWidth + pixelX);
    float4* imgPtr = (float4*)(&cuConstRendererParams.imageData[pixelOffset]);
    
    // Local accumulator for the pixel's color
    float4 pixelColor = *imgPtr;
    
    // Process all circles in sequential order
    for (int circleIdx = 0; circleIdx < cuConstRendererParams.numCircles; circleIdx++) {
        int index3 = 3 * circleIdx;
        
        // Read circle position and radius
        float3 p = *(float3*)(&cuConstRendererParams.position[index3]);
        float rad = cuConstRendererParams.radius[circleIdx];
        
        // Compute the bounding box of the circle in normalized coordinates
        float boxL = p.x - rad;
        float boxR = p.x + rad;
        float boxB = p.y - rad;
        float boxT = p.y + rad;
        
        // Check if the pixel center is within the circle
        float diffX = p.x - pixelCenterNorm.x;
        float diffY = p.y - pixelCenterNorm.y;
        float pixelDist = diffX * diffX + diffY * diffY;
        float maxDist = rad * rad;
        
        // Circle does not contribute to this pixel
        if (pixelDist > maxDist)
            continue;
        
        // Compute shading for this circle
        float3 rgb;
        float alpha;
        
        if (cuConstRendererParams.sceneName == SNOWFLAKES || 
            cuConstRendererParams.sceneName == SNOWFLAKES_SINGLE_FRAME) {
            const float kCircleMaxAlpha = .5f;
            const float falloffScale = 4.f;
            
            float normPixelDist = sqrt(pixelDist) / rad;
            rgb = lookupColor(normPixelDist);
            
            float maxAlpha = .6f + .4f * (1.f-p.z);
            maxAlpha = kCircleMaxAlpha * fmaxf(fminf(maxAlpha, 1.f), 0.f);
            alpha = maxAlpha * exp(-1.f * falloffScale * normPixelDist * normPixelDist);
        } else {
            // Simple: each circle has an assigned color
            rgb = *(float3*)&(cuConstRendererParams.color[index3]);
            alpha = .5f;
        }
        
        float oneMinusAlpha = 1.f - alpha;
        
        // Blend this circle's contribution with the current pixel color
        pixelColor.x = alpha * rgb.x + oneMinusAlpha * pixelColor.x;
        pixelColor.y = alpha * rgb.y + oneMinusAlpha * pixelColor.y;
        pixelColor.z = alpha * rgb.z + oneMinusAlpha * pixelColor.z;
        pixelColor.w = alpha + pixelColor.w;
    }
    
    // Write the final color to global memory (only once)
    *imgPtr = pixelColor;
}

void CudaRenderer::render() {
    // Use a 2D grid and block structure to match the image dimensions
    dim3 blockDim(16, 16);
    dim3 gridDim(
        (image->width + blockDim.x - 1) / blockDim.x,
        (image->height + blockDim.y - 1) / blockDim.y);
    
    kernelRenderPixels<<<gridDim, blockDim>>>();
    cudaDeviceSynchronize();
}
