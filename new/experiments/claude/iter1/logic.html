CUDA Renderer Fix

Problem Description

The current CUDA renderer implementation fails to produce correct images because it does not ensure atomic updates to the image data and does not preserve the required order of image updates. Specifically, the current implementation assigns one thread per circle, allowing multiple threads to update the same pixel simultaneously, resulting in race conditions. Furthermore, since threads may execute in any order, there's no guarantee that circles are processed in the required input order.

Problem Reasoning

The key issue is the current parallelization strategy. By assigning one thread per circle, multiple circles can contribute to the same pixel concurrently, leading to race conditions in the image update operations. The semi-transparent circle rendering requires that circles be processed in a specific order for proper blending. When multiple threads update the same pixel without coordination, we get the horizontal streaks visible in the buggy output images. These issues violate both the atomicity and ordering requirements specified in the assignment.

Proposed Remedy

Replace the current thread-per-circle parallelization strategy with a thread-per-pixel approach. Each thread will be responsible for processing all circles that affect its assigned pixel, in the order the circles were provided. This ensures both atomicity (since only one thread updates each pixel) and correct ordering (since each thread processes circles sequentially).

Remedy Reasoning

1) Why will this solution fix the problem?

This solution addresses both requirements directly:

  • Atomicity: By assigning exactly one thread to each pixel, we eliminate race conditions in pixel updates completely.
  • Order: Since each thread processes all circles in the original input order, the transparency blending will be correct.

2) What do you expect the program results to be after this change is implemented?

After implementing this change, I expect the program to pass all correctness tests. The images produced should no longer have horizontal streaks or other artifacts caused by race conditions. All scenes, including those with transparent circles, should render correctly with proper blending. While this solution prioritizes correctness over performance, it provides a solid foundation that could be optimized later if needed.

// kernelRenderCirclesOrdered -- (CUDA device code)
//
// Each thread renders a single pixel, processing all circles in order
__global__ void kernelRenderCirclesOrdered() {
    int pixelX = blockIdx.x * blockDim.x + threadIdx.x;
    int pixelY = blockIdx.y * blockDim.y + threadIdx.y;
    
    int imageWidth = cuConstRendererParams.imageWidth;
    int imageHeight = cuConstRendererParams.imageHeight;
    
    // Check if this thread's pixel is within the image bounds
    if (pixelX >= imageWidth || pixelY >= imageHeight)
        return;
    
    float invWidth = 1.f / imageWidth;
    float invHeight = 1.f / imageHeight;
    float2 pixelCenterNorm = make_float2(invWidth * (static_cast<float>(pixelX) + 0.5f),
                                        invHeight * (static_cast<float>(pixelY) + 0.5f));
    
    // Get a pointer to this pixel's color data
    float4* imgPtr = (float4*)(&cuConstRendererParams.imageData[4 * (pixelY * imageWidth + pixelX)]);
    
    // Process all circles in order
    for (int circleIndex = 0; circleIndex < cuConstRendererParams.numCircles; circleIndex++) {
        int index3 = 3 * circleIndex;
        
        // Read circle position and radius
        float3 p = *(float3*)(&cuConstRendererParams.position[index3]);
        float rad = cuConstRendererParams.radius[circleIndex];
        
        // Compute the distance from pixel center to circle center
        float diffX = p.x - pixelCenterNorm.x;
        float diffY = p.y - pixelCenterNorm.y;
        float pixelDist = diffX * diffX + diffY * diffY;
        float maxDist = rad * rad;
        
        // If pixel is within the circle, update its color
        if (pixelDist <= maxDist) {
            shadePixel(circleIndex, pixelCenterNorm, p, imgPtr);
        }
    }
}

void
CudaRenderer::render() {
    // Set up a 2D grid of threads, where each thread processes one pixel
    dim3 blockDim(16, 16);
    dim3 gridDim(
        (image->width + blockDim.x - 1) / blockDim.x,
        (image->height + blockDim.y - 1) / blockDim.y);
    
    kernelRenderCirclesOrdered<<<gridDim, blockDim>>>();
    cudaDeviceSynchronize();
}
