Optimized CUDA Circle Renderer

Problem Description

The current CUDA implementation is inefficient because it performs multiple global memory operations for each circle-pixel interaction. Specifically, in the shadePixel function, we read from global memory, blend the new color, and write back to global memory for each circle that affects a pixel, resulting in excessive memory traffic.

Problem Reasoning

When analyzing the performance issues, I noticed that the current implementation reads and writes to global memory (which is slow) for each circle that affects a pixel. For scenes with many circles overlapping a single pixel, this creates a significant performance bottleneck. Additionally, the implementation checks every circle against every pixel, even though most circles only affect a small portion of the image.

The current kernelRenderCirclesOrdered ensures correctness by processing circles in order for each pixel, but its memory access pattern is suboptimal. We can maintain this correct ordering while reducing global memory operations.

Proposed Remedy

I propose optimizing the kernel by:

  1. Reading each pixel's color once at the beginning of the kernel.
  2. Accumulating all circle contributions to the pixel color in a local variable.
  3. Writing the final accumulated color back to global memory once at the end.
  4. Using the circleInBoxConservative test to quickly filter out circles that cannot possibly affect a pixel.

Remedy Reasoning

This solution will fix the problem by drastically reducing the number of global memory operations. Global memory access is one of the slowest operations in CUDA, so minimizing these operations should significantly improve performance.

1) Why will this solution fix the problem?
By accumulating color contributions locally and only writing back once, we reduce global memory operations from O(circles_affecting_pixel) to O(1) per pixel. The circle-box test provides a quick way to skip circles that don't affect a pixel without having to perform the more expensive distance calculations.

2) Expected results:
I expect all test cases to still render correctly (maintaining both atomicity and ordering requirements), but with significantly improved performance. The improvement should be most noticeable in scenes with many circles or where multiple circles overlap (like rand100k, rand1M, and micro2M).

Code Implementation

__global__ void kernelRenderCirclesOptimized() {
    int pixelX = blockIdx.x * blockDim.x + threadIdx.x;
    int pixelY = blockIdx.y * blockDim.y + threadIdx.y;
    
    int imageWidth = cuConstRendererParams.imageWidth;
    int imageHeight = cuConstRendererParams.imageHeight;
    
    // Check if this pixel is within the image bounds
    if (pixelX >= imageWidth || pixelY >= imageHeight)
        return;
    
    // Compute the pixel center and bounds in normalized coordinates
    float invWidth = 1.f / imageWidth;
    float invHeight = 1.f / imageHeight;
    float2 pixelCenterNorm = make_float2(invWidth * (static_cast<float>(pixelX) + 0.5f),
                                         invHeight * (static_cast<float>(pixelY) + 0.5f));
    float pixelLeft = invWidth * (static_cast<float>(pixelX) - 0.5f);
    float pixelRight = invWidth * (static_cast<float>(pixelX) + 0.5f);
    float pixelBottom = invHeight * (static_cast<float>(pixelY) - 0.5f);
    float pixelTop = invHeight * (static_cast<float>(pixelY) + 0.5f);
    
    // Get a pointer to this pixel's color data
    float4* imgPtr = (float4*)(&cuConstRendererParams.imageData[4 * (pixelY * imageWidth + pixelX)]);
    
    // Read the current pixel color once
    float4 color = *imgPtr;
    
    // Process circles in order (preserving order requirement)
    for (int i = 0; i < cuConstRendererParams.numCircles; i++) {
        int index3 = 3 * i;
        
        // Read circle position and radius
        float3 p = *(float3*)(&cuConstRendererParams.position[index3]);
        float rad = cuConstRendererParams.radius[i];
        
        // Quick check if this circle might affect this pixel
        if (circleInBoxConservative(p.x, p.y, rad, 
                                    pixelLeft, pixelRight,
                                    pixelTop, pixelBottom)) {
            
            // Compute the distance from pixel center to circle center
            float diffX = p.x - pixelCenterNorm.x;
            float diffY = p.y - pixelCenterNorm.y;
            float pixelDist = diffX * diffX + diffY * diffY;
            float maxDist = rad * rad;
            
            // If pixel is within the circle, update its color
            if (pixelDist <= maxDist) {
                float3 rgb;
                float alpha;
                
                // Compute the shading value
                if (cuConstRendererParams.sceneName == SNOWFLAKES || cuConstRendererParams.sceneName == SNOWFLAKES_SINGLE_FRAME) {
                    const float kCircleMaxAlpha = .5f;
                    const float falloffScale = 4.f;
                    
                    float normPixelDist = sqrt(pixelDist) / rad;
                    rgb = lookupColor(normPixelDist);
                    
                    float maxAlpha = .6f + .4f * (1.f-p.z);
                    maxAlpha = kCircleMaxAlpha * fmaxf(fminf(maxAlpha, 1.f), 0.f);
                    alpha = maxAlpha * exp(-1.f * falloffScale * normPixelDist * normPixelDist);
                } else {
                    // simple: each circle has an assigned color
                    rgb = *(float3*)&(cuConstRendererParams.color[index3]);
                    alpha = .5f;
                }
                
                float oneMinusAlpha = 1.f - alpha;
                
                // Update the local color (in registers, not global memory)
                color.x = alpha * rgb.x + oneMinusAlpha * color.x;
                color.y = alpha * rgb.y + oneMinusAlpha * color.y;
                color.z = alpha * rgb.z + oneMinusAlpha * color.z;
                color.w = alpha + color.w;
            }
        }
    }
    
    // Write the final color back to the image once
    *imgPtr = color;
}

void
CudaRenderer::render() {
    // Set up a 2D grid of threads, where each thread processes one pixel
    dim3 blockDim(16, 16);
    dim3 gridDim(
        (image->width + blockDim.x - 1) / blockDim.x,
        (image->height + blockDim.y - 1) / blockDim.y);

    kernelRenderCirclesOptimized<<<gridDim, blockDim>>>();
    cudaDeviceSynchronize();
}

Optimizing CUDA Circle Renderer

Problem Description

The current implementation of kernelRenderCirclesOrdered processes all circles for each pixel, regardless of whether the circle actually intersects with the pixel. This is inefficient, especially for scenes with many circles (e.g., rand10k, rand100k, rand1M, micro2M) where only a fraction of circles overlap with any given pixel. Additionally, the implementation performs unnecessary global memory operations for each pixel, reading and writing the pixel color multiple times.

Problem Reasoning

Examining the current renderer, I noticed two major inefficiencies:

  1. For each pixel, the current implementation checks every circle in the scene, performing expensive distance calculations, even for circles that are far away from the pixel.
  2. For each circle that contributes to a pixel, it performs a global memory read, update, and write operation, which is inefficient due to the high latency of GPU global memory accesses.

These inefficiencies significantly slow down the renderer, especially in scenes with many circles. The renderer would benefit from early rejection of circles that don't affect a pixel and by reducing global memory operations.

Proposed Remedy

I propose two key optimizations:

  1. Add a quick bounding box test to reject circles that definitely don't intersect with the pixel, using the provided circleInBoxConservative function.
  2. Use a local accumulator for the pixel color, reducing global memory operations from multiple read-writes per pixel to just one read at the beginning and one write at the end.

Remedy Reasoning

The proposed optimizations will improve performance while maintaining correctness for the following reasons:

  1. The bounding box test will quickly reject circles that definitely don't intersect with a pixel, reducing computation by avoiding expensive distance calculations and circle-pixel tests for irrelevant circles. This should be particularly effective for scenes with many small circles.
  2. Using a local accumulator will significantly reduce global memory traffic by accumulating color contributions in fast registers rather than making repeated reads and writes to global memory. This addresses a key bottleneck in GPU programming.

Importantly, these optimizations preserve both required invariants:

  • Order: We still process all circles in the original input order for each pixel.
  • Atomicity: By using a local accumulator and only writing back to global memory once, we ensure that image updates are atomic.

I expect these changes to significantly improve performance across all test cases, with the largest improvements in scenes with many circles (rand10k, rand100k, rand1M, micro2M) where most circles don't overlap with most pixels.

Code

__global__ void kernelRenderCirclesOrdered() {
    int pixelX = blockIdx.x * blockDim.x + threadIdx.x;
    int pixelY = blockIdx.y * blockDim.y + threadIdx.y;

    int imageWidth = cuConstRendererParams.imageWidth;
    int imageHeight = cuConstRendererParams.imageHeight;

    // Check if this thread's pixel is within the image bounds
    if (pixelX >= imageWidth || pixelY >= imageHeight)
        return;

    float invWidth = 1.f / imageWidth;
    float invHeight = 1.f / imageHeight;
    float2 pixelCenterNorm = make_float2(invWidth * (static_cast<float>(pixelX) + 0.5f),
                                        invHeight * (static_cast<float>(pixelY) + 0.5f));

    // Get a pointer to this pixel's color data
    float4* imgPtr = (float4*)(&cuConstRendererParams.imageData[4 * (pixelY * imageWidth + pixelX)]);

    // Use a local accumulator for the pixel color instead of constantly reading/writing to global memory
    float4 pixelColor = *imgPtr;

    // Define the pixel's box for conservative circle intersection test
    float halfInvWidth = 0.5f * invWidth;
    float halfInvHeight = 0.5f * invHeight;
    float boxL = pixelCenterNorm.x - halfInvWidth;
    float boxR = pixelCenterNorm.x + halfInvWidth;
    float boxB = pixelCenterNorm.y - halfInvHeight;
    float boxT = pixelCenterNorm.y + halfInvHeight;

    // Process all circles in order (maintaining the order invariant)
    for (int circleIndex = 0; circleIndex < cuConstRendererParams.numCircles; circleIndex++) {
        int index3 = 3 * circleIndex;

        // Read circle position and radius
        float3 p = *(float3*)(&cuConstRendererParams.position[index3]);
        float rad = cuConstRendererParams.radius[circleIndex];

        // Quick bounding box test to reject circles that definitely don't intersect with the pixel
        if (!circleInBoxConservative(p.x, p.y, rad, boxL, boxR, boxT, boxB)) {
            continue;
        }

        // Compute the distance from pixel center to circle center
        float diffX = p.x - pixelCenterNorm.x;
        float diffY = p.y - pixelCenterNorm.y;
        float pixelDist = diffX * diffX + diffY * diffY;
        float maxDist = rad * rad;

        // If pixel is within the circle, update its color
        if (pixelDist <= maxDist) {
            // Compute the color of the circle at this pixel
            float3 rgb;
            float alpha;

            if (cuConstRendererParams.sceneName == SNOWFLAKES || cuConstRendererParams.sceneName == SNOWFLAKES_SINGLE_FRAME) {
                const float kCircleMaxAlpha = .5f;
                const float falloffScale = 4.f;

                float normPixelDist = sqrt(pixelDist) / rad;
                rgb = lookupColor(normPixelDist);

                float maxAlpha = .6f + .4f * (1.f-p.z);
                maxAlpha = kCircleMaxAlpha * fmaxf(fminf(maxAlpha, 1.f), 0.f); // kCircleMaxAlpha * clamped value
                alpha = maxAlpha * exp(-1.f * falloffScale * normPixelDist * normPixelDist);
            } else {
                // simple: each circle has an assigned color
                rgb = *(float3*)&(cuConstRendererParams.color[index3]);
                alpha = .5f;
            }

            float oneMinusAlpha = 1.f - alpha;

            // Update the local accumulator with this circle's contribution
            pixelColor.x = alpha * rgb.x + oneMinusAlpha * pixelColor.x;
            pixelColor.y = alpha * rgb.y + oneMinusAlpha * pixelColor.y;
            pixelColor.z = alpha * rgb.z + oneMinusAlpha * pixelColor.z;
            pixelColor.w = alpha + pixelColor.w;
        }
    }

    // Write the final color back to global memory (only once per pixel)
    *imgPtr = pixelColor;
}
