<h2>Optimized CUDA Circle Renderer</h2>

<h3>Strategy</h3>
<p>After analyzing the current CUDA renderer implementation, I'm planning to optimize it with the following approach:</p>
<ol>
  <li>Keep the current pixel-centric approach where each thread processes one pixel for correctness</li>
  <li>Load circle data into shared memory in batches to significantly reduce global memory access</li>
  <li>Maintain atomicity and correct ordering of circle blending</li>
  <li>Use early rejection with bounding box tests to avoid processing circles that don't affect a pixel</li>
  <li>Accumulate pixel color locally before writing once to global memory</li>
</ol>

<h3>Reasoning</h3>
<p>The current implementation is correct but inefficient because:</p>
<ol>
  <li><strong>Global Memory Bottleneck:</strong> Each pixel thread repeatedly accesses global memory for every circle's data, which is extremely slow. By loading circle data into shared memory in batches, we can reduce global memory traffic significantly.</li>
  <li><strong>Processing Unnecessary Circles:</strong> While the bounding box test is already used, we're still looping through all circles for every pixel. By using shared memory batching, we maintain this test while reducing memory access overhead.</li>
  <li><strong>Maintaining Correctness Requirements:</strong> Our approach preserves the two critical requirements:
    <ul>
      <li>Atomicity: By using a local accumulator and only writing to global memory once</li>
      <li>Order: By still processing circles in their original order for each pixel</li>
    </ul>
  </li>
  <li><strong>Performance Intuition:</strong> The test results show that our renderer is particularly slow for scenes with many circles (rand1M, micro2M). This confirms that the main bottleneck is in circle data access from global memory, which our shared memory approach will address.</li>
</ol>

<h3>Code</h3>

```c
#define BLOCK_SIZE 16      // 16x16 threads per block
#define CIRCLES_PER_BATCH 64  // Process 64 circles at a time in shared memory

// kernelRenderCircles -- (CUDA device code)
//
// Render all circles on the image. Each thread renders a single pixel.
// Uses shared memory to load circle data in batches for efficiency.
__global__ void kernelRenderCircles() {
    int imageX = blockIdx.x * blockDim.x + threadIdx.x;
    int imageY = blockIdx.y * blockDim.y + threadIdx.y;

    int width = cuConstRendererParams.imageWidth;
    int height = cuConstRendererParams.imageHeight;

    if (imageX >= width || imageY >= height)
        return;

    // Create a local accumulator for this pixel
    float4 pixelColor;
    
    // Get current image color from global memory
    int offset = 4 * (imageY * width + imageX);
    pixelColor = *(float4*)(&cuConstRendererParams.imageData[offset]);
    
    // Normalized pixel center position
    float invWidth = 1.f / width;
    float invHeight = 1.f / height;
    float2 pixelCenterNorm = make_float2(invWidth * (static_cast<float>(imageX) + 0.5f),
                                         invHeight * (static_cast<float>(imageY) + 0.5f));
    
    // Shared memory to store circle data
    __shared__ float3 sharedPositions[CIRCLES_PER_BATCH];
    __shared__ float sharedRadii[CIRCLES_PER_BATCH];
    __shared__ int sharedIndices[CIRCLES_PER_BATCH];
    
    int numCircles = cuConstRendererParams.numCircles;
    
    // Process circles in batches to reduce global memory access
    for (int batchStart = 0; batchStart < numCircles; batchStart += CIRCLES_PER_BATCH) {
        int batchSize = min(CIRCLES_PER_BATCH, numCircles - batchStart);
        
        // Load circle data into shared memory
        int linearThreadIdx = threadIdx.y * blockDim.x + threadIdx.x;
        for (int i = linearThreadIdx; i < batchSize; i += BLOCK_SIZE * BLOCK_SIZE) {
            int circleIdx = batchStart + i;
            int index3 = 3 * circleIdx;
            
            sharedPositions[i] = *(float3*)(&cuConstRendererParams.position[index3]);
            sharedRadii[i] = cuConstRendererParams.radius[circleIdx];
            sharedIndices[i] = circleIdx;
        }
        
        __syncthreads();
        
        // Process all circles in this batch
        for (int i = 0; i < batchSize; i++) {
            int circleIdx = sharedIndices[i];
            float3 p = sharedPositions[i];
            float rad = sharedRadii[i];
            
            // Skip circle if it doesn't affect this pixel using bounding box test
            if (!circleInBoxConservative(p.x, p.y, rad, 
                                       pixelCenterNorm.x - invWidth/2, 
                                       pixelCenterNorm.x + invWidth/2,
                                       pixelCenterNorm.y + invHeight/2, 
                                       pixelCenterNorm.y - invHeight/2))
                continue;
            
            // The circle might affect this pixel - compute precise shading
            shadePixel(circleIdx, pixelCenterNorm, p, &pixelColor);
        }
        
        __syncthreads();
    }
    
    // Write the final color for this pixel to global memory once
    *(float4*)(&cuConstRendererParams.imageData[offset]) = pixelColor;
}

void CudaRenderer::render() {
    // 16x16 threads per block = 256 threads
    dim3 blockDim(BLOCK_SIZE, BLOCK_SIZE);
    dim3 gridDim(
        (image->width + blockDim.x - 1) / blockDim.x,
        (image->height + blockDim.y - 1) / blockDim.y);

    kernelRenderCircles<<<gridDim, blockDim>>>();
    cudaDeviceSynchronize();
}
```

The implementation makes several key optimizations:

1. **Shared Memory Batching**: Instead of having each pixel thread repeatedly access global memory for every circle, we load circle data (position, radius, index) into shared memory in batches. This significantly reduces global memory bandwidth usage.

2. **Parallel Loading of Circle Data**: The threads in each block cooperatively load circle data into shared memory, ensuring efficient memory access patterns.

3. **Early Circle Rejection**: We continue to use `circleInBoxConservative` to quickly reject circles that don't affect a pixel before performing more expensive shading operations.

4. **Local Color Accumulation**: We accumulate the color for each pixel locally and only write to global memory once at the end, reducing global memory writes.

5. **Preserved Correctness**: By still processing circles in their original order for each pixel and using a local accumulator, we maintain both the atomicity and ordering requirements.

This approach should provide a significant performance improvement over the current implementation while maintaining correctness across all test cases.
