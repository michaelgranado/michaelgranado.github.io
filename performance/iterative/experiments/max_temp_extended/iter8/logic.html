CUDA Circle Renderer Optimization

Strategy

My optimization strategy focuses on several key areas:

  1. Use a tile-based approach with optimized circle culling to drastically reduce unnecessary work
  2. Implement smarter batch processing with scene-dependent batch sizes
  3. Reduce memory access costs by caching frequently used data in shared memory
  4. Add aggressive early-exit optimizations for tiles with no circle intersections
  5. Improve memory access patterns for better coalescing
  6. Pre-compute and cache frequently used values to reduce redundant math
  7. Minimize thread divergence in critical loops

Reasoning

The test results reveal several performance bottlenecks in the current implementation:

First, the performance degrades significantly on scenes with many circles (rand10k, rand100k, rand1M, micro2M). This indicates that we're not efficiently filtering out circles that don't contribute to each tile. Analyzing the test results, these scenes run 3-7x slower than the reference implementation.

Second, the current solution is already correct but inefficient. It processes all circles for each tile, which is wasteful especially for scenes with many small circles where most don't affect a given tile. The micro2M test especially shows this issue - with 2 million tiny circles, we're doing far too many unnecessary intersection checks.

My strategy addresses these issues by:

  • Optimized circle culling: Efficiently determine which circles actually intersect with each tile to minimize unnecessary work
  • Adaptive batch sizing: Use larger batch sizes for scenes with many circles to amortize synchronization costs
  • Fast batch rejection: Skip entire batches of circles that don't intersect with the current tile
  • Squared radius caching: Pre-compute radius-squared values to eliminate a multiplication in the inner loop
  • Shared memory utilization: Leverage shared memory to cache circle data for all threads in a block
  • Early exit paths: Add checks to avoid unnecessary work for out-of-bounds pixels

#define MAX_BATCH_SIZE 4096

// Helper to dynamically select batch size based on scene complexity

    if (numCircles > 1000000) return 4096;     // For extremely large scenes

    if (numCircles > 10000) return 1024;       // For large scenes

__global__ void kernelRenderCirclesOptimized() {
    // Calculate pixel coordinates for this thread
    int pixelX = blockIdx.x * TILE_SIZE + threadIdx.x;
    int pixelY = blockIdx.y * TILE_SIZE + threadIdx.y;
    int linearThreadIdx = threadIdx.y * TILE_SIZE + threadIdx.x;
    int threadsPerBlock = TILE_SIZE * TILE_SIZE;
    
    int width = cuConstRendererParams.imageWidth;
    int height = cuConstRendererParams.imageHeight;
    
    // Early exit if pixel is out of bounds
    bool validPixel = (pixelX < width && pixelY < height);
    
    // Initialize pixel data only if valid (reduces register pressure for invalid pixels)
    float4 pixelColor;
    int offset;
    float2 pixelCenterNorm;
    
    if (validPixel) {
        // Load current pixel color
        offset = 4 * (pixelY * width + pixelX);
        pixelColor = *(float4*)(&cuConstRendererParams.imageData[offset]);
        
        // Compute normalized pixel coordinates (only once)
        float invWidth = 1.f / width;
        float invHeight = 1.f / height;
        pixelCenterNorm = make_float2(
            invWidth * (static_cast<float>(pixelX) + 0.5f),
            invHeight * (static_cast<float>(pixelY) + 0.5f)
        );
    }
    
    // Calculate tile bounds for circle culling (once per tile)
    float invWidth = 1.f / width;
    float invHeight = 1.f / height;
    float boxL = invWidth * (blockIdx.x * TILE_SIZE);
    float boxR = invWidth * (min((blockIdx.x + 1) * TILE_SIZE, width));
    float boxT = invHeight * (min((blockIdx.y + 1) * TILE_SIZE, height));
    float boxB = invHeight * (blockIdx.y * TILE_SIZE);
    
    // Determine batch size based on scene complexity
    int numCircles = cuConstRendererParams.numCircles;
    int batchSize = getBatchSize(numCircles);
    
    // Shared memory declarations - using extern to adapt to different batch sizes
    extern __shared__ char sharedMem[];
    float3* positions = (float3*)sharedMem;
    float* radiusSquared = (float*)(positions + batchSize);  // Store r² directly
    bool* intersects = (bool*)(radiusSquared + batchSize);
    bool* anyIntersection = (bool*)(intersects + batchSize);
    
    // Process all circles in batches
    for (int batchStart = 0; batchStart < numCircles; batchStart += batchSize) {
        int batchEnd = min(batchStart + batchSize, numCircles);
        int currentBatchSize = batchEnd - batchStart;
        
        // Reset intersection flag for this batch
        if (linearThreadIdx == 0) {
            *anyIntersection = false;
        }
        __syncthreads();
        
        // Collaborative loading of circle data and intersection testing
        for (int i = linearThreadIdx; i < currentBatchSize; i += threadsPerBlock) {
            int circleIdx = batchStart + i;
            int index3 = 3 * circleIdx;
            
            float3 p = *(float3*)(&cuConstRendererParams.position[index3]);
            float rad = cuConstRendererParams.radius[circleIdx];
            
            positions[i] = p;
            radiusSquared[i] = rad * rad;  // Pre-compute r² to avoid multiplication later
            
            // Check if circle intersects with this tile
            bool doesIntersect = circleInBoxConservative(p.x, p.y, rad, boxL, boxR, boxT, boxB);
            intersects[i] = doesIntersect;
            
            // Update tile intersection flag if any circle intersects
            if (doesIntersect) {
                *anyIntersection = true;
            }
        }
        
        __syncthreads();
        
        // Skip this entire batch if no circles intersect with the tile
        if (!(*anyIntersection)) {
            continue;
        }
        
        // Process only valid pixels and only circles that intersect with this tile
        if (validPixel) {
            for (int i = 0; i < currentBatchSize; i++) {
                // Skip non-intersecting circles quickly
                if (!intersects[i]) 
                    continue;
                
                float3 p = positions[i];
                float maxDist = radiusSquared[i];
                
                // Check if pixel is inside circle
                float diffX = p.x - pixelCenterNorm.x;
                float diffY = p.y - pixelCenterNorm.y;
                float pixelDist = diffX * diffX + diffY * diffY;
                
                if (pixelDist <= maxDist) {
                    // Apply shading for this circle
                    shadePixel(batchStart + i, pixelCenterNorm, p, &pixelColor);
                }
            }
        }
        
        __syncthreads();
    }
    
    // Write the final accumulated color back to global memory (only once)
    if (validPixel) {
        *(float4*)(&cuConstRendererParams.imageData[offset]) = pixelColor;
    }
}

    // Set up block and grid dimensions
    dim3 blockDim(TILE_SIZE, TILE_SIZE);
    dim3 gridDim(
        (image->width + TILE_SIZE - 1) / TILE_SIZE,
        (image->height + TILE_SIZE - 1) / TILE_SIZE
    );
    
    // Determine appropriate batch size based on scene complexity
    int batchSize = 512;
    if (numCircles >= 10000) batchSize = 1024;
    if (numCircles >= 100000) batchSize = 2048;
    if (numCircles >= 1000000) batchSize = 4096;
    
    // Calculate required shared memory size
    size_t sharedMemSize = batchSize * (sizeof(float3) + sizeof(float) + sizeof(bool)) + sizeof(bool);
    
    // Launch kernel with dynamic shared memory allocation
    kernelRenderCirclesOptimized<<<gridDim, blockDim, sharedMemSize>>>();
    cudaDeviceSynchronize();
}

High-Performance CUDA Circle Renderer

Strategy

My strategy for optimizing the circle renderer focuses on five key areas:

  1. Efficient circle culling: Use a two-level culling approach - first at the tile level, then at the pixel level, to minimize unnecessary computations.
  2. Batch processing with early termination: Process circles in optimally-sized batches with an early exit mechanism for tiles that don't intersect with any circles in a batch.
  3. Memory access optimization: Minimize global memory operations by using local registers for color accumulation and only writing back once per pixel.
  4. Collaborative data loading: Have threads in a block cooperatively load circle data into shared memory for better memory coalescing and reduced redundancy.
  5. Dynamic adaptation: Adjust batch sizes based on scene characteristics to optimize performance across different test cases.

Reasoning

Analysis of the existing implementation reveals several critical performance issues:

Memory Access and Redundancy Issues: The current implementation repeatedly loads circle data from global memory and performs redundant circle-box intersection tests. This is especially problematic for scenes with many circles like rand100k, rand1M, and micro2M, where the test results show the largest performance gaps.

Inefficient Circle Culling: The existing approach doesn't efficiently determine which circles actually affect each tile, causing excessive computation, especially for scenes with many small circles like micro2M.

Lack of Early Exits: The current code processes all circles even when they don't intersect with the current tile, leading to wasted computation.

Suboptimal Memory Pattern: The implementation makes multiple global memory accesses for each pixel update, which is inefficient compared to accumulating in registers and writing back once.

My solution addresses these issues while maintaining the critical correctness requirements:

Ordering Requirement: By processing circles in their original order (within each batch and across batches), we ensure correct transparency rendering.

Atomicity Requirement: By accumulating colors in thread-local registers and only writing back once, we eliminate the need for atomic operations while ensuring correct image updates.

The adaptive batch sizing approach optimizes performance across different scene types. For scenes with few circles (like rgb), smaller batches minimize overhead. For scenes with many small circles (like micro2M), larger batches amortize synchronization costs and enable more efficient culling.

Main Rendering Kernel

__global__ void kernelRenderCirclesOptimized() {
    // Calculate pixel coordinates for this thread
    int pixelX = blockIdx.x * TILE_SIZE + threadIdx.x;
    int pixelY = blockIdx.y * TILE_SIZE + threadIdx.y;

    int width = cuConstRendererParams.imageWidth;
    int height = cuConstRendererParams.imageHeight;

    // Early exit if pixel is out of bounds
    if (pixelX >= width || pixelY >= height)
        return;

    // Calculate pixel center in normalized coordinates
    float invWidth = 1.f / width;
    float invHeight = 1.f / height;
    float2 pixelCenterNorm = make_float2(
        invWidth * (static_cast(pixelX) + 0.5f),
        invHeight * (static_cast(pixelY) + 0.5f)
    );

    // Load current pixel color into a register for accumulation
    int offset = 4 * (pixelY * width + pixelX);
    float4 pixelColor = *(float4*)(&cuConstRendererParams.imageData[offset]);

    // Calculate tile bounds for circle culling (only once per thread)
    float boxL = invWidth * (blockIdx.x * TILE_SIZE);
    float boxR = invWidth * (min((blockIdx.x + 1) * TILE_SIZE, width));
    float boxT = invHeight * (min((blockIdx.y + 1) * TILE_SIZE, height));
    float boxB = invHeight * (blockIdx.y * TILE_SIZE);

    // Get total number of circles and determine batch size
    int numCircles = cuConstRendererParams.numCircles;
    int batchSize = getBatchSize(numCircles);

    // Thread index for collaborative loading
    int linearThreadIdx = threadIdx.y * TILE_SIZE + threadIdx.x;
    int threadsPerBlock = TILE_SIZE * TILE_SIZE;

    // Shared memory declarations - using extern to adapt to different batch sizes
    extern __shared__ char sharedMem[];
    float3* positions = (float3*)sharedMem;
    float* radii = (float*)(positions + batchSize);
    bool* intersects = (bool*)(radii + batchSize);
    bool* anyIntersection = (bool*)(intersects + batchSize);

    // Process all circles in batches
    for (int batchStart = 0; batchStart < numCircles; batchStart += batchSize) {
        int batchEnd = min(batchStart + batchSize, numCircles);
        int currentBatchSize = batchEnd - batchStart;

        // Reset intersection flag for this batch
        if (linearThreadIdx == 0) {
            *anyIntersection = false;
        }
        __syncthreads();

        // Collaborative loading of circle data
        for (int i = linearThreadIdx; i < currentBatchSize; i += threadsPerBlock) {
            int circleIdx = batchStart + i;
            int index3 = 3 * circleIdx;

            float3 p = *(float3*)(&cuConstRendererParams.position[index3]);
            float rad = cuConstRendererParams.radius[circleIdx];

            positions[i] = p;
            radii[i] = rad;

            // Check if circle intersects with this tile
            bool doesIntersect = circleInBoxConservative(p.x, p.y, rad, boxL, boxR, boxT, boxB);
            intersects[i] = doesIntersect;

            // Update the flag if any circle intersects
            if (doesIntersect) {
                *anyIntersection = true;
            }
        }

        __syncthreads();

        // Skip this batch if no circle intersects with the tile
        if (!(*anyIntersection)) {
            continue;
        }

        // Process only the circles that intersect with this tile
        for (int i = 0; i < currentBatchSize; i++) {
            if (!intersects[i])
                continue;

            float3 p = positions[i];
            float rad = radii[i];

            // Check if this pixel is within the circle
            float diffX = p.x - pixelCenterNorm.x;
            float diffY = p.y - pixelCenterNorm.y;
            float pixelDist = diffX * diffX + diffY * diffY;
            float maxDist = rad * rad;

            if (pixelDist <= maxDist) {
                // Apply shading for this circle to our local accumulator
                shadePixel(batchStart + i, pixelCenterNorm, p, &pixelColor);
            }
        }

        __syncthreads();
    }

    // Write the final accumulated color back to global memory (only once)
    *(float4*)(&cuConstRendererParams.imageData[offset]) = pixelColor;
}

Key Optimizations

  1. Adaptive Batch Sizing: Dynamically adjusts batch size based on scene complexity to balance synchronization overhead with memory utilization.
  2. Early Exit for Tiles: Completely skips processing batches where no circles intersect with the current tile, significantly improving performance for scenes with sparse circles.
  3. Local Register-Based Accumulation: Accumulates pixel colors in registers instead of repeatedly reading/writing to global memory, reducing memory bandwidth requirements.
  4. Two-Level Culling: First tests circle-tile intersection, then circle-pixel intersection, minimizing unnecessary computation.
  5. Collaborative Loading: Threads cooperatively load circle data for better memory coalescing, reducing memory access latency.
  6. Minimal Synchronization: Only synchronizes threads when necessary, reducing overhead.
  7. Shared Memory Utilization: Uses shared memory to cache circle data that will be accessed by all threads in a block.

Correctness Guarantees

The implementation maintains both correctness requirements:

  • Atomicity: By accumulating pixel colors in thread-local registers and only writing back once, we eliminate race conditions without needing explicit atomic operations.
  • Ordering: Circles are processed in their original input order (within each batch and across batches), ensuring correct transparency rendering.
