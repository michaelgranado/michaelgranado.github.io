Incremental Plan for Implementing Solution 4: Cooperative Tile Processing with Pre-Filtering

This plan outlines incremental steps to refactor the provided correct-but-slow CUDA renderer (`kernelRenderCirclesTiled`) towards Solution 4: Cooperative Tile Processing with Pre-Filtering. The core idea is to have threads within a block cooperate to process only the circles relevant to their tile, using shared memory to reduce global memory access and redundant computations. Each step aims to maintain correctness (atomicity and order) so the code should pass the ./checker.py tests after each step, while progressively improving performance.

Starting Point: The provided `correct_unoptimized_code` which uses a pixel-parallel approach (`kernelRenderCirclesTiled`). Each thread handles one pixel, loops through all circles, performs a coarse tile culling check, accumulates color locally in registers, and writes the final pixel color once to global memory. This is correct but slow due to O(P*N) complexity.

Step 1: Build Tile-Specific Circle List in Shared Memory (Serial Build)

Goal: Stop threads from looping over all N circles. Instead, have one thread per block identify circles overlapping the block's tile and store their indices in shared memory. All threads in the block then process only this smaller list.

Implementation Details:
  1. Define a reasonable maximum number of circles expected to overlap a single tile (e.g., MAX_CIRCLES_PER_TILE). This might require some tuning or analysis of scenes, but start with a generous estimate (e.g., 1024 or 2048). Be mindful of shared memory limits. Allocate a shared memory array: __shared__ int s_tileCircleIndices[MAX_CIRCLES_PER_TILE];
  2. Allocate a shared integer to count circles in the list: __shared__ int s_tileCircleCount;
  3. Designate one thread per block (e.g., if (threadIdx.x == 0 && threadIdx.y == 0)) to perform the filtering:
    • Initialize s_tileCircleCount = 0;
    • This thread loops from circleIndex = 0 to numCircles - 1.
    • Inside the loop, read the circle's position and radius.
    • Use the exact circleInBox test (from circleBoxTest.cu_inl) to check if the current circle overlaps the block's tile boundaries (calculated similarly to how tileL, tileR, tileT, tileB were calculated in the original kernel).
    • If the circle overlaps the tile and s_tileCircleCount < MAX_CIRCLES_PER_TILE, store the circleIndex in the shared list: s_tileCircleIndices[s_tileCircleCount] = circleIndex; and increment s_tileCircleCount. (Handle potential overflow if needed, though initially, assume it fits).
  4. Synchronize the block after the filtering thread is done: __syncthreads();
  5. Modify the main processing loop for all threads:
    • Instead of looping 0 to numCircles - 1, loop from int i = 0; i < s_tileCircleCount; ++i.
    • Inside the loop, get the actual circle index: int circleIndex = s_tileCircleIndices[i];
    • Read the required circle data (position p, radius rad) from global memory using this circleIndex.
    • Call shadePixel(circleIndex, pixelCenterNorm, p, accumulatedColor); as before. Note: The coarse circleInBoxConservative check from the original loop is no longer needed here, as we're only processing circles already known to overlap the tile via the more precise circleInBox test during list building. The check inside shadePixel is still necessary for the exact pixel coverage.
Correctness Check:
  • Order: Preserved. The designated thread builds the shared list s_tileCircleIndices by iterating through circles in their original global order (0 to N-1). All pixel threads then process circles from this shared list in the order they were added.
  • Atomicity: Preserved. Each thread still accumulates color locally in registers (accumulatedColor) and performs a single write to global memory at the end.
Expected Outcome: Code should be correct. Performance should improve significantly for scenes where circles are sparse relative to tiles (most scenes), as pixel threads now loop over far fewer circles (s_tileCircleCount instead of numCircles). The main bottleneck is now the serial list building by thread 0.

Step 2: Cooperatively Load Circle Data into Shared Memory

Goal: Reduce global memory bandwidth consumption in the main pixel processing loop by loading the position and radius data for the tile's relevant circles into shared memory once, rather than having every thread load it individually.

Implementation Details (Building on Step 1):
  1. Allocate additional shared memory arrays to hold the data for the circles identified in Step 1:
    • __shared__ float3 s_tileCirclePositions[MAX_CIRCLES_PER_TILE];
    • __shared__ float s_tileCircleRadii[MAX_CIRCLES_PER_TILE];
  2. After the __syncthreads(); that follows the list building (from Step 1):
  3. Implement cooperative loading:
    • Each thread in the block calculates an index j = threadIdx.y * blockDim.x + threadIdx.x; (linear thread index within the block).
    • Use a grid-stride loop or simple `if` check: if (j < s_tileCircleCount).
    • Inside the `if`, the thread is responsible for loading data for the j-th circle in the tile's list.
      • Get the global circle index: int circleIndex = s_tileCircleIndices[j];
      • Read position and radius from global memory: float3 pos = *(float3*)(&cuConstRendererParams.position[3 * circleIndex]); and float rad = cuConstRendererParams.radius[circleIndex];
      • Store them into the shared arrays: s_tileCirclePositions[j] = pos; and s_tileCircleRadii[j] = rad;
    • Alternatively, use a strided loop for loading if `s_tileCircleCount` can be larger than the block size: `for (int j = linearThreadIndex; j < s_tileCircleCount; j += blockDim.x * blockDim.y)`
  4. Synchronize the block again to ensure all data loading is complete before any thread starts processing: __syncthreads();
  5. Modify the main processing loop (the one iterating from i = 0 to s_tileCircleCount):
    • Get the global circle index: int circleIndex = s_tileCircleIndices[i]; (still needed for shadePixel potentially, e.g., if color isn't loaded into shared memory).
    • Read position and radius directly from shared memory: float3 p = s_tileCirclePositions[i]; and float rad = s_tileCircleRadii[i];.
    • Call shadePixel(circleIndex, pixelCenterNorm, p, accumulatedColor);. Note: You might need to slightly modify `shadePixel` or pass `rad` directly if it wasn't already, to avoid it re-reading radius from global memory. Ensure `shadePixel` still uses the correct `circleIndex` if it needs to look up color from global memory.
Correctness Check:
  • Order: Preserved. The order of processing is still dictated by the loop over s_tileCircleIndices, which was built respecting the original order in Step 1.
  • Atomicity: Preserved. Local register accumulation and single final write remain unchanged.
Expected Outcome: Code should remain correct. Performance should improve further, especially in scenes with high overlap (many circles per tile), as the global memory reads for position/radius inside the main loop are replaced by faster shared memory reads. The serial list building by thread 0 remains the primary bottleneck. Shared memory usage increases.

After implementing each step, run ./checker.py to verify correctness and observe the performance changes.
