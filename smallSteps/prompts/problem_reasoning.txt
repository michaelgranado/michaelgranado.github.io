I observed that the core loop in kernelRenderCirclesTiled runs from circleIndex = 0 to numCircles - 1 for every single pixel thread. The circleInBoxConservative check inside this loop helps skip the shadePixel call for circles far from the tile, but the loop itself, along with the memory reads for circle position and radius, still executes for all circles. For scenes like rand1M (1 million circles) and a 1024x1024 image, each of the 1 million+ threads executes a loop 1 million times. The vast majority of these iterations are wasted work because a pixel's tile is typically overlapped by only a small fraction of the total circles. This suggests that pre-filtering the circles relevant to a tile before the pixel processing loop could yield substantial performance improvements.
